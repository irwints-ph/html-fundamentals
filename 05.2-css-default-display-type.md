# 📌 Default `display` types of common HTML elements

HTML elements already come with a **built-in display behavior** (even before you write CSS).

---

# 🧱 Block-level elements (default: `display: block`)

These take full width and start on a new line.

### Common ones:

| Element    | Default behavior            |
| ---------- | --------------------------- |
| `div`      | block                       |
| `p`        | block                       |
| `h1`–`h6`  | block                       |
| `section`  | block                       |
| `article`  | block                       |
| `header`   | block                       |
| `footer`   | block                       |
| `nav`      | block                       |
| `ul`, `ol` | block                       |
| `li`       | block (inside list context) |
| `form`     | block                       |

---

### 📌 Example behavior:

```txt id="b1k9aa"
[ div ]
[ div ]
[ div ]
```

Each one starts on a new line.

---

# 🧵 Inline elements (default: `display: inline`)

These flow inside text and don’t break lines.

### Common ones:

| Element       | Default behavior |
| ------------- | ---------------- |
| `span`        | inline           |
| `a`           | inline           |
| `strong`      | inline           |
| `em`          | inline           |
| `b`, `i`, `u` | inline           |
| `label`       | inline           |

---

### 📌 Example:

```txt id="c2m1bb"
text <span>inline</span> text <a>link</a>
```

---

# 🔳 Inline-block (NOT default, but important)

These are usually set manually:

```css id="k2p9dd"
display: inline-block;
```

Used for:

* buttons
* badges
* nav items

---

# 🧱 Special cases (important nuance)

## 🧩 `li` (list items)

Even though `li` is block by default:

```html id="l9q2ff"
<ul>
  <li>Item 1</li>
  <li>Item 2</li>
</ul>
```

They behave like block elements but are controlled by the parent list.

---

## 🧩 `img` (special case)

```css id="i8x2hh"
img {
  display: inline;
}
```

But behavior is “inline-block-like”:

* sits inline with text
* but can take width/height

---

## 🧩 `input`, `button`

```css id="n3v7jj"
input, button {
  display: inline-block;
}
```

That’s why they can sit side-by-side but still have dimensions.

---

# ⚡ Quick mental map

```txt id="m1z9kk"
BLOCK      → layout structure (div, section, p)
INLINE     → text flow (span, a)
INLINE-BLK → controls (button, input, img-like behavior)
```

---

# 🎯 Why this matters

Most beginner layout bugs come from not knowing:

* why things stack (block)
* why things sit inline (inline)
* why width doesn’t work (inline limitation)
